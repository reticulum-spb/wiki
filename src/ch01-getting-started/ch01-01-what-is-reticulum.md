# Что такое Reticulum

**Reticulum Network Stack** — это сетевой стек для построения децентрализованных сетей поверх практически любых каналов связи.

Хотя Reticulum решает ту же задачу, что и любой сетевой стек — доставляет данные из одной точки в другую через
ряд промежуточных узлов, — подход Reticulum существенно отличается от классических сетевых технологий. Разберем его ключевые
особенности, чтобы понять, что нам может предложить RNS.

## Ключевые особенности

### Независимость от каналов связи

Одна из главных особенностей Reticulum — возможность объединять совершенно разные каналы связи.

Например:

```text
Ноутбук
   │ Wi-Fi
   ▼
Raspberry Pi
   │ Serial
   ▼
RNode
   │ LoRa радио, 20 км
   ▼
RNode
   │ USB
   ▼
Raspberry Pi
   │ Ethernet
   ▼
   ПК
```

Для конечного приложения вся эта конструкция остаётся одной сетью Reticulum. Отдельные участки могут сильно отличаться 
по скорости. Ethernet способен передавать сотни мегабит в секунду, а дальний радиоканал — всего сотни байт в секунду.
Reticulum спроектирован так, чтобы такие каналы могли существовать в одной сети.

### Децентрализация

Reticulum — это инструмент для построения множества независимых сетей.

Сети могут работать самостоятельно, объединяться друг с другом и снова разделяться. Для этого не нужен общий управляющий сервер.

В Reticulum нет централизованного управления адресным пространством. Каждый может выделять столько адресов, сколько ему нужно, и тогда, когда они нужны.
Адреса не привязаны к расположению в сети: при перемещении узла адрес можно сохранить.

### Безопасность

Данные шифруются от отправителя до конечного получателя. Промежуточные узлы пересылают пакеты, но не могут прочитать их содержимое.
Объявления о доступности получателей **(Announce)** подписываются, что позволяет проверять их подлинность.

Для общения можно установить **Link** — зашифрованное соединение с [прямой секретностью (*forward secrecy*)](https://ru.wikipedia.org/wiki/Perfect_forward_secrecy):
компрометация долговременного ключа не раскрывает ранее записанный обмен. Для отдельных пакетов без Link
прямая секретность доступна при включении механизма смены ключей — *ratchets*.

Исключение из шифрования — открытые пакеты **Plain** для локального обмена. Через промежуточные узлы они не передаются.

### Адреса приложений

Вместо сочетания IP-адреса и порта Reticulum использует **destination** — точку назначения приложения.
Длина адреса точки назначения — 128 бит. У индивидуального получателя адрес связан с именем назначения и открытым ключом.
Одна криптографическая идентичность (**Identity**) может иметь несколько таких точек назначения.

### Автоматическая маршрутизация

Получатель распространяет подписанное объявление — **announce**. Транспортные узлы узнают из него,
куда пересылать пакеты. Каждому достаточно знать следующий шаг к получателю; полная карта сети не требуется.
После перемещения новое объявление позволяет обновить путь.

Пересылка чужого трафика включается отдельно: обычный узел по умолчанию не становится маршрутизатором.

### Отсутствие адреса отправителя

Пакеты Reticulum не содержат адреса источника. Инициатор может установить Link, не раскрывая свою Identity получателю.
Её передача выполняется отдельно, если этого требует приложение.

### Работа на медленных каналах

Reticulum рассчитан на низкую пропускную способность и большие задержки. Сеть может работать на каналах
со скоростью более 5 бит/с и с поддержкой пакетов размером 500+ байт. Установление Link требует всего трёх пакетов.

### Средства надёжной передачи

Стек предоставляет криптографически проверяемые подтверждения доставки, механизм запросов и ответов,
передачу больших объёмов данных с автоматическим разбиением и контролем целостности,
а также **Channel** и **Buffer** для надёжной последовательной доставки.
Приложение выбирает и реализует подходящий механизм обмена.

### Независимость от интернета

Для работы Reticulum не требуется IP: сеть может полностью состоять из радиоканалов и последовательных соединений.
При этом существующую IP-сеть можно использовать как транспорт.
